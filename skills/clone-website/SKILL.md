# Skill：把网站复刻成「全站内闭环」的静态站

## 触发场景
- 用户说「复刻这个网站」「仿一个这个页面」「把它存成静态站」「部署到我的域名/Pages」「把详情页也带上」「全部指向站内」。
- **默认按整站全量理解**：首页 + 所有栏目页 + 所有列表视图（tab/筛选的每种组合）+ 全部详情页；用户只想要单页时他会明说。
- 目标：本地能开、结构还原、原站能点的站内都能点、**页内所有链接一律指向站内，唯一例外是项目源码的 GitHub 链接保留真实外跳**，除此之外不把人甩回原站。
- 来源：为 Riven 复刻 Hacker News、HelloGitHub（60+ 详情页、标签页、榜单三榜、月刊 126 期、文章 20 篇）等站点的实操经验。

## 硬性验收标准（定义「复刻完成」）
用户说「全部复刻」时，以下 10 条缺一不可，做不到的项必须在汇报里点明，不许含糊带过：
1. **列表卡片一律指向站内详情页**：把卡片 `<a href="https://原站/...">` 改写为 `href="./repo/xxx.html"`，并给卡片加 `data-card="1"` 之类标记，同步改掉依赖旧选择器的筛选/过滤 JS。
2. **详情页数量对得上列表条数**：列表有多少条，站内就生成多少张详情页，一张都不少（生成后必须打印计数核对）。
3. **标签页 / 分类页 / 作者页 / 分页 / 顶部导航 / 页脚**等所有入口也都指向站内页面；标签点进站内标签页，不点回原站。
4. **导航栏与每个 tab 都能点开**：导航里的每个栏目、页面上的每个 tab（月度/年度/周榜、精选/全部、热门/新晋、按年份/按分类切换等）都必须指向真实存在的站内 `.html`。**不允许保留 `?rank_by=monthly` 这类回原站的参数链接，不允许 `href="#"`、`javascript:` 假链接**。tab 的每种参数组合都要有对应站内页（例：`rank/index.html` 一页承载月度/年度/周榜三张榜，或 `rank/monthly.html`、`rank/yearly.html`、`rank/weekly.html` 三页）。
5. **频道页成套产出**：对照入口清单逐个建页，常见组合——
   - `rank/` 榜单（月度/年度/周榜各自的站内页）
   - `periodical/` 系列/期刊目录 + **每一期**一页 `periodical/<期号>.html`
   - `article/` 文章列表 + 每篇正文 `article/<slug>.html`
   - `list/` 全部条目、`tag/` 标签总览、（原站有则加）`search/`、分页 `page/2.html` 之类
6. **页内几乎零外链，GitHub 源码链接是唯一例外（硬约束）**：全站 `site/**/*.html` 里，指向站外的**可点击链接只允许一类**——项目源码/仓库的 GitHub 地址（形如 `https://github.com/<owner>/<repo>`，写成 `<a href="…" target="_blank" rel="noopener noreferrer">`，加明显按钮样式，文字如「在 GitHub 上查看 owner/repo ↗」）。除此之外，指向**原站页面**的可点链接（详情页「去原站查看」按钮、导航、页脚、侧栏、图片包链、统计与广告脚本）数量必须为 **0**，历史遗留的非 GitHub `target="_blank"` 一律清掉。非 GitHub 的溯源信息只允许用**纯文本**写一行（例：`来源：hellogithub.com（本页为离线镜像）`），不能是可点的 `<a>`。
7. **静态资源全本地化**：图片/CSS/JS/字体下载到 `assets/` 并改相对路径；`srcset`、CSS `background:url()` 一并处理，断网打开不缺图不缺样式。
8. **完整性核对表**：跑脚本输出一张对照表，逐项列出「原站数量 vs 站内数量」——导航项、tab 组合数、列表条数、详情页数、期刊期数、文章数、标签数、分页数、非 GitHub 外链条数、GitHub 源码链接条数。**任何一项对不上就得先补齐再上线，不能带着差值报告完成。**
9. **本地逐个点一遍**：浏览器打开本地站点，导航、tab、卡片、返回首页、分页、标签全部点过，确认都留在站内（地址栏一直是本地路径）；顺手点一下详情页的 GitHub 按钮，确认新标签能跳出正确仓库。
10. **线上脚本化校验**：部署后统计「站内链接数 / 非 GitHub 外链数（应为 0）/ `href="#"` 数（应为 0）/ GitHub 源码链接数（每个详情页应 ≥1）」、站内链接目标文件存在率（应为 100%），逐个频道页与 tab 目标 URL 探测状态码，抽查详情页/文章页/期刊页 200 且含标题与中文正文、且 GitHub 链接可点，结果贴给用户。

## 部署域名约定（用户已定，不用再问）
- 复刻站统一挂在用户的 Cloudflare 自有域名 **senlinlu.cn** 下。
- 域名规则：**前缀沿用原站前缀 + 后缀 senlinlu.cn**。例：原站 `kaiyuanbang.cn` → 复刻站 `kaiyuanbang.senlinlu.cn`。
- 绑定方式：在项目 `wrangler.jsonc` 里加
  `"routes": [{ "pattern": "<前缀>.senlinlu.cn", "custom_domain": true }]`，
  然后 `npx wrangler deploy`，wrangler 自动建 DNS 记录，无需手动去面板添加。
- 同时保留 `"workers_dev": true`，让旧的 `*.workers.dev` 链接继续可用（否则加了 routes 后 workers.dev 会被自动禁用、老链接变 404）。
- 部署后用 `curl -s -D - "https://<前缀>.senlinlu.cn/"` 验证 200，并确认自定义响应头正常。
- 这是公开域名，任何拿到链接的人都能访问；用户要求私密时才加访问口令。

## 前置确认
- **自动获取（不要问用户）**：目标网址、项目目录（桌面 `<站名>-clone`）、部署仓库名与项目名按用户既有约定直接用，重复任务不再确认。
- **需要问用户的情况**：只在「是否要上线到公网」信息真的缺、且猜错代价大时问一次，最好带推荐答案。复刻范围默认整站全量，不再问「整站还是单页」。
- 版权与合规：仅供个人学习/自用，不替换对方品牌、不冒用官方名义；上线时页面底部用纯文本标注来源（见验收标准第 6 条，非 GitHub 来源不给外链）。

## 执行步骤
1. **取原页**：`open_application browser` → `open_url` 打开目标页并 `screen_snapshot` 确认；再用 `curl -L "<url>" -o raw.html` 拿原始 HTML（比渲染后的 DOM 更全）。
2. **枚举全站入口（复刻范围由这一步决定，最容易漏）**：把原站当成一张图逐个列清——
   - 顶部导航、页脚、侧栏里的每个栏目链接（含下拉菜单里的项）
   - 列表页每个 tab 与筛选，并记下它们真实切换的 URL 参数（`?sort_by=featured`、`?rank_by=yearly`、`?period=weekly`…）
   - 分页、期号网格、系列/专题/年度归档入口
   - 详情页类型（项目详情、文章正文、期刊页、作者页…）
   产出 `routes.json`：入口名 → 站内目标路径 → 数据来源。**原站有几种 tab，站内就要有几张页面**；这一步漏掉的入口，上线后用户一定会点，然后抱怨「点不动」。
3. **摸清数据来源（SPA 必须做）**：优先找官方 API / 站内 JSON（`/api/...`、页面里的 `__NEXT_DATA__`、`/_next/data/*.json`、`sitemap.xml`）。Next.js 等前端渲染站的 HTML 只是空壳，翻页与 tab 都是客户端路由，靠存 HTML 抓不到多页数据。把每个入口对应的数据接口、参数取值写进 `routes.json`。
3b. **接口不全时不许降级**：接口只给部分数据（例如月刊只放出最近 3 期的项目、榜单只给 Top 100）时，**不能就此做「索引 + 跳原站」收尾**，而要直接按 URL 规律逐个抓原站页面（`/periodical/33/`、`/periodical/34/`…、榜单分页、期刊内的项目链接）把内容补齐，直到 `routes.json` 里每个入口的条目都能在站内成页。真拿不到的（登录后可见、纯前端动态搜索）才在汇报里单独列出。
4. **建目录与脚本**：`<站名>-clone/` 下 `site/`（成品，含 `repo/`、`tag/`、`rank/`、`periodical/`、`article/`、`list/`、`page/`）、`assets/`（资源）、`detail-raw/`（原始详情页 HTML）；资源替换、详情页生成、频道页生成各写一个 Node 脚本，别手工改长 HTML。
5. **本地化资源**：脚本遍历 `src`/`href`/`srcset`/`url()`，逐个下载到 `assets/` 并改相对路径；失败的外链跳转、统计脚本、广告直接删标签，不留死链。
6. **批量抓详情页**：对每个条目 `fetch https://原站/详情路径`，要求 200 且含 `__NEXT_DATA__`（或结构化数据）才落盘；带 `User-Agent`，每次请求间 `sleep 500~700ms`，已存在且体积正常的文件跳过（可断点续跑）。
7. **解析结构化数据**：从 `__NEXT_DATA__` / JSON-LD 提取 `title / full_name / url / author / description / summary / primary_lang / lang_color / stars_str / forks / tags / updated_at / share_user`，存 `details.json`（先打一次字段名，防止取错路径）。**务必保留 `full_name`/仓库地址字段**，它就是后面 GitHub 按钮的数据来源。
8. **生成站内详情页**：脚本套模板批量输出 `site/repo/<owner>__<name>.html`（扁平文件名避免深层目录），页内包含：`← 返回首页`（`../index.html`）、中文标题、仓库名、作者/语言/星标/Fork/更新时间/推荐人、简介卡片、标签（→ 站内标签页）、**GitHub 源码按钮**（`<a class="src" href="https://github.com/<owner>/<repo>" target="_blank" rel="noopener noreferrer">在 GitHub 上查看 <owner>/<repo> ↗</a>`，带按钮样式，`full_name` 为唯一数据源）、非 GitHub 来源行用纯文本。**除 GitHub 源码按钮外，不放任何指向原站的可点链接**。复用站点既有 CSS 或内联样式保持一致观感。
9. **站内化改写首页与既有页面**：脚本把卡片 `<a target="_blank" href="https://www.原站/...">` 替换为 `href="./repo/xxx.html" data-card="1"`，并**顺手清掉页脚/侧栏/导航里所有指向原站的链接**（署名与来源改成纯文本）；同步把依赖 `a[href^="https://原站"]` 的筛选 JS 选择器改为 `a[data-card]`。替换前后各打印一条匹配结果，确认真的改到了。
   - **清零外链时按域名白名单跳过 `github.com`**：不管是正则还是遍历，过滤条件都写成「站外且非 github.com」才删/改；别图省事把 `https://` 全清，否则 GitHub 源码链接会被一起降级成纯文本（这就是用户事后要求「GitHub 链接改回来」的原因）。
9b. **生成站内标签页**：按标签聚合条目，每标签输出一页 `site/tag/<slug>.html`（页内卡片→`../repo/xxx.html`，标出数量），并输出 `site/tag/index.html`（全部标签 + 每标签条目数）。把详情页的标签、列表页侧栏/筛选里的标签统一改成 `../tag/<slug>.html`。
10. **生成频道页与 tab 页（全站复刻的关键一步）**：按第 2、3b 步的 `routes.json` 写 `build-pages.js`，每个入口一页，落盘位置固定为 `site/rank/`、`site/periodical/`、`site/article/`、`site/list/`、`site/page/`。要求：
    - **tab 一律用站内真链接**（`./rank/monthly.html`、`./periodical/index.html`），不留 query 参数、不留 `#`；
    - 频道页里的条目卡片照第 9 步规则指站内详情页；
    - 每个 tab/筛选组合都要有站内页，页面顶部还要有互相切换的站内 tab 条；
    - 分页要完整：`page/2.html`、`page/3.html`… 直到最后一页，页脚「下一页/末页」都是站内链接。
11. **本地校验（必做）**：`open_url file:///<绝对路径>/site/index.html` → `screen_snapshot` 核对样式/图片/字体，控制台无 404；点一张卡片进详情页、点「返回首页」能回来；**逐个点导航与 tab**，确认都跳到站内页面而不是原站；详情页的 GitHub 按钮要在新标签打开正确仓库。
12. **跑完整性核对表与链接扫描（上线前卡口）**：
    - 遍历 `site/**/*.html`，统计**非 GitHub 站外链接数**、`href="#"` 数、站内链接目标缺失数——三项都必须为 0；同时统计 GitHub 源码链接数，正文含项目的详情页应 ≥1；
    - 打印对照表：导航项数、tab 组合数、列表条数、详情页数、期刊期数、文章数、标签数、分页数，**原站 vs 站内逐项对齐**；
    - 有差值就先补页，补完再跑一次，通过才进入部署。
13. **部署 + 线上校验**：`npx wrangler deploy`；然后跑 Node fetch 校验：各频道页/tab 目标 URL 状态码全为 200（或 307→200）、抽查详情页与文章页含中文内容、**GitHub 源码链接仍在且可点、非 GitHub 外链数为 0**，结果贴给用户。
14. **汇报**：一句话给全站闭环结论（原站 N 个入口 → 站内 N 个页面、详情页 N 个、非 GitHub 外链 0、`href="#"` 0、GitHub 源码链接 N 条）+ 本地路径 + 部署地址；确实取不到的少数内容单独列出，不谎报完成。

## 命令与工具注意
- Windows 下 shell 别用 `&&`、`&` 串多条 node 命令，容易整体报错；一次跑一个脚本，输出重定向到日志再 `type 日志` 读（工具报 error 但消息里常有真实 stdout，按内容判断）。
- 批量抓取分成每批 20 条、带 sleep 跑，避免命令超时；超时就缩小批次继续，已完成文件靠「存在即跳过」续跑。
- 页面里的中文在 PowerShell 写文件时容易变问号：用 Node/`write_file` 写 UTF-8（无 BOM），别用 PowerShell here-string 拼中文。
- 别为生成页面去开浏览器/Word（WPS）；普通站点用 Node + `write_file` 足够。
- 用 PowerShell 打印含中文的 HTML 验证结果会变乱码（如「??��」），判断对错看标签结构与链接数量，别被乱码吓到。
- 需要重新部署时用 `npx wrangler deploy`，不要手动删 DNS；wrangler 输出较长，放后台跑再读日志尾部。

## 常见坑
- **「只复刻了首页和详情页」是最大返工原因**：导航「月刊/榜单/文章」和「月度/年度」这些 tab 还是原站参数链接，用户点了一点动静都没有（跳回原站首页或原站刷新），反馈就是「这个点不动、那个点不了」。必须给每个 tab、每个栏目建独立站内页面，并在第 11 步后逐个点一遍验证。
- **接口有上限就以为复刻不全**：看到「只返回最近 3 期」就做索引跳原站，等于把用户甩回原站。正确做法是按 URL 规律补抓每一期/每一页，站内自己成页。
- **把 GitHub 源码链接也清成纯文本**（本技能旧版本的偏差）：项目源码地址是用户唯一明确要保留的可点外链，必须写成真 `<a>`，别做成「复制地址到浏览器打开」这类文字提示；用户会直接要求改回来。**原站页面链接要清，GitHub 源码链接要留**，两回事别混。
- **留着「去原站查看」按钮**：除了 GitHub 源码按钮，页内任何指向原站的可点外链都要清掉；非 GitHub 来源只用纯文本写一行。
- **批量修链接要能重复跑**：恢复/改写 GitHub 链接这类操作写成独立 Node 脚本（正则匹配旧文案 → 输出标准 `<a class="src">`），打印「扫描 N 页 / 改写 N 页 / 未匹配 N 页」，跑完再全站扫一遍确认 0 残留，比手工改安全。
- **SPA / Next.js 站点**：直接存 HTML 只有空壳，分页与 tab 是客户端路由；要从 API/JSON 拿数据，用「多页 + 真链接」重建，别指望原站的 JS 在离线也帮你渲染。
- **Cloudflare Pages 的 clean URL**：上传 `rank/index.html` 后，线上访问 `/rank/index.html` 会 307 跳到 `/rank/`，页面里写 `./rank/index.html` 完全没问题；但校验脚本要按无扩展名 URL（`/rank/`）检查，看到 307 不是出错。
- **侧栏「热门标签」留死链**：原站侧栏常是 `href="#"` 或是全站标签（本地数据集里根本没有），照抄就成了点不动的死链；必须按抓到的真实标签重建侧栏，并保证全站 `href="#"` 数量为 0。
- **卡片直接外链原站 = 没复刻**：只扒了首页 HTML，卡片 href 还是 github.com，用户点一下就跑了。必须在第 9 步统一改写并校验外链数。
- 只存 HTML 不本地化资源 → 断网即白屏；详情页里的 `srcset`、CSS `background:url()` 最容易漏。
- 列表条数 ≠ 详情页数 → 计数核对，别凭感觉说「全部复刻好了」。
- 生成详情页时索引错位（用 `repos[1]` 当样本）会导致样本与标题不符，抓取和解析都要以 `owner/name` 为唯一键。
- 页面里的 `href="/xxx"` 绝对路径在本地会跳飞，统一改成相对路径或站内页面。
- 加 `routes` 自定义域名后 workers.dev 会默认关闭，要保留就显式写 `"workers_dev": true`。
- 改完 HTML 后旧的筛选/过滤脚本选择器会失效，页面看似正常但筛选全空，记得一起改。

## 自动更新（原站新增内容自动进站，可选）
用户要“每天自动同步原站”时，在项目里做一个 `update.js`，用系统计划任务定时跑，流程固定为：
1. 抓原站列表（优先用官方 API/结构化接口，其次解析首页卡片）→ 与本地数据文件比对，找出新增条目。
2. 只抓新增条目的详情页，缓存原始 HTML，老条目跳过；重新提取数据文件。
3. 重建**所有**数据驱动的页面（详情页、标签页、榜单页、期刊页、文章页、全部条目页、分页），把新增卡片按站内链接插入首页（新卡片一开始就写成 `./repo/xxx.html` + `data-card="1"`，不要留原站/外链）；频道页的 tab 链接同样保持站内；新增详情页要带 GitHub 源码按钮（数据里没有 `full_name` 就先生成、别留下无按钮的页面）。
4. **本地校验通过才部署**：非 GitHub 外链必须为 0、死链 `href="#"` 必须为 0、站内链接指向的文件必须都存在、含项目的详情页 GitHub 链接数 ≥1；校验不过就终止，并把改动前的文件备份到 `backup/时间戳/` 供回滚。
5. 部署后做线上校验（首页站内链接数、随便抽一个新详情页含 GitHub 链接、标签/榜单/期刊索引页返回码），全部写进 `update-log.txt`。
6. 备份目录只保留最近 7 份，避免无限增长。

Windows 计划任务注意：
- 用 `New-ScheduledTaskAction -Execute 'C:\Program Files\nodejs\node.exe' -Argument '"…\update.js"' -WorkingDirectory …` 注册；
  **不要**把带空格的项目路径直接塞进 `schtasks /TR`，它会在空格处拆成 Execute/Arguments，任务报 0x80070002「找不到指定的文件」。
- 批处理启动脚本必须写 **CRLF** 行尾，否则 cmd 会把多行拼错（报 “'dp0\"' 不是内部或外部命令”）。
- 让 node 自己写日志文件；批处理 stdout 重定向到**另一个**文件，重定向到同一个日志会 EBUSY。
- 写 .ps1 时别用无 BOM 的 UTF-8 中文，PowerShell 5.1 会按 ANSI 读导致解析报错（改成英文输出或用 BOM）。
